# Intent

GET /api/projects incorrectly exposes the reserved global config.yaml file as if it were a real project. Reproduction: with the config directory (SGT_CONFIG, default ~/.config/sergeant) containing the reserved global config.yaml (holding only machine-wide settings like dev_root and default_identity) plus real per-project YAML files, GET /api/projects lists a project named config with empty repos. Expected: /api/projects returns only real registered project YAMLs and excludes the reserved global config.yaml file. Root cause per prior investigation: internal/config/list.go ListProjects globs every *.yaml/*.yml file in the config dir with no exclusion for the reserved global config filename. Fix ListProjects to skip the reserved global config file (config.yaml specifically, matching whatever constant/name the codebase already uses to refer to the global config file elsewhere, e.g. in LoadProject or wherever dev_root/default_identity get read) so it never appears in the projects list.
