## 2026-09-25 - SQLite Indexing Penalty Avoidance
**Learning:** SQLite suffers a performance penalty ("USE TEMP B-TREE FOR ORDER BY") on queries that filter and immediately sort without a covering composite index. Sorting by `created_at` after filtering by a foreign key like `run_id` requires composite indexes (e.g., `(run_id, created_at ASC)`) to use the index for sorting.
**Action:** When creating new core tables that will be queried by a foreign key and ordered by a timestamp, always define a composite index containing both columns in the exact sort direction rather than a single index on the foreign key.
