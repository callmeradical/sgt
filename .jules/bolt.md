## 2026-09-28 - Avoid SQLite TEMP B-TREE penalty for idempotency key queries
**Learning:** Queries on the `deliveries` table filtering by `idempotency_key` and sorting by `created_at DESC, id DESC` (or `ASC`) trigger a full table scan (or inefficient partial index usage) and require a "TEMP B-TREE" for sorting in SQLite, which degrades performance as the table grows.
**Action:** Always add a composite index (e.g., `idx_deliveries_idempotency_key_created_at_id`) that includes both the filtered column and the ordered columns in the exact sort direction to eliminate the TEMP B-TREE penalty and utilize efficient index lookups.
